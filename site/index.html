Your whiteboard,

Drawhaus is the infrastructure around Excalidraw's editor — accounts, workspaces, real-time collaboration, share links, a REST API, and an MCP server so AI agents can draw. You run it, you own the database.

docker compose up

Needs Docker, or Node ≥ 24 and PostgreSQL 16. Then open localhost:5173.

The honest version

One person built this. One person maintains it.

I made Drawhaus to own my diagrams and to learn full-stack by shipping something I actually use. I run one instance, for me and a handful of friends. It's MIT, it's v0.12, and there is no company behind it.

Excalidraw is the editor, and it stays theirs. It's the best drawing tool I've used and there is nothing about it worth rebuilding. Drawhaus is the part around it: persistence, accounts, sharing, an API, and a way for agents to draw into the same canvas you do.

If that's the trade you want, the whole thing is docker compose up. If you need SSO and an SLA, there's a section below that says so plainly.

What it does

Everything around the editor

The infrastructure layer Excalidraw's open-source build doesn't ship, because it was never meant to.

It's your box

Diagrams live in your PostgreSQL, on your machine. Nothing phones home, and there is no tier that unlocks a feature.

  • Docker Compose locally, Kamal for a VPS
  • Three-step setup wizard — no .env editing to get started
  • Scheduled database backups with retention
  • Integration secrets encrypted at rest (AES-256-GCM)
  • Audit log, rate limiting, hardened cookies and headers

People in the same canvas

Concurrent editing with element-level merge, not a lock — two people can work on the same diagram without one of them waiting.

  • Live cursors, presence and viewport follow
  • Workspaces with admin, editor and viewer roles
  • Share links with a role and an expiry date
  • Guest access by token — no account needed to join
  • Threaded comments with a resolve workflow
  • Snapshots you can preview and restore

Somewhere for the diagrams to live

Folders, search, thumbnails and starred boards, so a diagram you drew four months ago is still findable.

  • Seven built-in templates, plus your own
  • PNG and SVG export, .excalidraw import
  • Read-only embeds for a wiki or a README
  • Google Drive backup on save, if you want it
  • Signed webhooks on diagram events

Three ways in

Humans, code and agents draw the same diagram

A diagram an agent created is the same element array as one you drew by hand, in the same table. No format translation, no flat image you can't edit afterwards. 

# REST — OpenAPI 3.1 spec, API-key auth
curl -H "Authorization: Bearer $DRAWHAUS_API_KEY" \
     https://draw.example.com/v1/diagrams

# MCP — Claude Code, Cursor, VS Code
claude mcp add drawhaus \
  -e DRAWHAUS_URL=http://localhost:4000 \
  -e DRAWHAUS_API_KEY=dhk_... \
  -- npx @drawhaus/mcp

Mermaid and PlantUML paste straight into the canvas as editable shapes. @drawhaus/mcp is published to GitHub Packages — setup is in its README.

Run it

Three steps, about five minutes

  1. Clone it

    git clone https://github.com/rodacato/drawhaus.git

  2. Start the stack

    Frontend, backend, PostgreSQL and Redis with hot reload. The defaults work — copying .env.example is optional.

    docker compose up

  3. Make yourself admin

    Open http://localhost:5173. On an empty database it sends you to the setup wizard, and the first account registered becomes the admin.

Putting it on a real box? config/deploy.*.yml holds the Kamal setup — kamal-proxy, images on ghcr.io, TLS terminated upstream. GETTING_STARTED.md covers all three paths — Compose, Dev Container and bare metal — plus what to do when it doesn't come up.

What this is not

Before you spend an afternoon on it

  • Not a hosted service. There is no drawhaus.com to sign up for. If you don't run a server, this gives you nothing.
  • Not for enterprises that need SSO/SAML, compliance audit trails or a 99.99% SLA. It's a single-VPS tool.
  • Not a design tool. If you want pixel-perfect UI work, this is the wrong shape — it's for diagrams and sketches.
  • Not for people who don't want to run Docker. Self-hosted means you are your own ops team, including the day it breaks.
